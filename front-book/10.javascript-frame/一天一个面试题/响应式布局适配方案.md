# rem+flexible.js 响应式布局原理与实践

## 技术原理

rem+flexible.js 方案通过 JS 动态设置 html 根元素的 font-size，使 1rem 始终等于设计稿宽度的 1/10（如 375px 设计稿，1rem=37.5px），页面所有尺寸均用 rem 单位表达。这样不同屏幕宽度下，所有元素会等比缩放，达到高适配、强一致性的移动端响应式效果。

核心步骤：

1. 监听窗口 resize/orientationchange，动态计算当前 viewport 宽度。
2. 限制最大宽度（如 540px，防止 iPad/PC 拉伸变形）。
3. 设置 html 的 font-size = viewportWidth / 10。
4. 页面所有宽高、间距、圆角等用 rem 单位编写。

优点：
- 适配主流移动端，体验高度一致
- 设计/开发/测试协作简单
- 代码简洁，维护成本低

缺点：
- 需引入 flexible.js 脚本
- PC/大屏适配需兜底
- 字体建议用 px，避免系统缩放影响

# vw/vh 响应式布局原理与实践

## 技术原理

vw/vh 单位是 CSS3 新增的视口单位，1vw=视口宽度的1%，1vh=视口高度的1%。直接用 vw/vh 编写所有尺寸，无需 JS 参与，天然自适应所有屏幕。

核心步骤：
1. 设计稿尺寸等比换算为 vw/vh 单位（如 375px 设计稿，1vw=3.75px）。
2. 页面所有宽高、间距、圆角等用 vw/vh 单位编写。

优点：
- 代码极简，无需 JS
- 适配所有屏幕，体验流畅
- 兼容主流移动端浏览器

缺点：
- 低端机部分兼容性问题
- 字体缩放、滚动条等细节需关注
- 设计/开发需统一 vw 换算标准

# 媒体查询（Media Query）响应式布局原理

## 技术原理

通过 @media 规则为不同屏幕宽度设置不同样式断点，实现多端适配。常用于 PC/移动端混合页面或复杂响应式场景。

核心步骤：
1. 设计断点（如 600px、900px、1200px）
2. 针对每个断点编写不同的样式规则
3. 结合 flex/grid 等布局方案灵活适配

优点：
- 适合多端/复杂场景
- 兼容性极好
- 可与任意布局方案组合

缺点：
- 样式维护复杂，断点设计需谨慎
- 代码量大，易冗余

---

# 方案对比与选型建议

| 方案             | 适用场景         | 维护成本 | 兼容性 | 体验一致性 | 典型问题           |
|------------------|------------------|----------|--------|------------|--------------------|
| rem+flexible.js  | 移动端高适配     | 低       | 好     | 高         | 需引入JS，字体问题 |
| vw/vh            | 移动端/响应式    | 低       | 较好   | 高         | 字体/滚动条细节    |
| 媒体查询         | 多端/复杂场景    | 高       | 极好   | 取决于实现 | 断点维护           |

---

> 建议：
> - 移动端主流推荐 rem+flexible.js 或 vw/vh，优先保证体验一致性和开发效率。
> - PC/多端混合场景建议媒体查询配合 flex/grid。
> - 字体、边框等细节建议用 px，避免系统缩放影响。
